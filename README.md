# Stellar — Railway deployment

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/TEMPLATE_CODE)

Deploy Stellar, an AI Business Operating System, with one click. The Railway
template runs the public prebuilt image and connects to your own hosted
Supabase project for Postgres, Auth, and Storage.

> Maintainers: replace `TEMPLATE_CODE` in the button above with the template
> code generated by Railway after publishing (see [Maintainer](#maintainer)).

## What gets deployed

- **One Railway service** (`main`) running
  `ghcr.io/app-corp/stellar:1.0.0`, a `linux/amd64` Next.js standalone image.
- **No Railway Postgres.** The database is your Supabase Postgres project.
- **No build on Railway.** Railway pulls the public image from GHCR.
- Pre-deploy runs Prisma migrations, RBAC seed, root-admin bootstrap, and
  Supabase Storage bucket/asset bootstrap.

## Prerequisites

You need a [Supabase](https://supabase.com/dashboard) project and:

1. **Project URL** — Project Settings → API.
2. **Anon public key** — Project Settings → API.
3. **Service-role secret key** — Project Settings → API. Keep it secret.
4. **Session pooler connection string** — Connect → Session pooler (port
   `5432`). This is IPv4 and works from Railway. Replace `<password>` with your
   database password. URL-encode reserved characters.
5. **Admin email and password** for the first Stellar account.

Optional: a custom domain, AI provider keys (`GOOGLE_GENERATIVE_AI_API_KEY`,
`REPLICATE_API_TOKEN`), and `NEXT_PUBLIC_PEXELS_API_KEY`.

## Deploy

1. Click **Deploy on Railway**.
2. Fill in the six values above.
3. Deploy and watch the pre-deploy logs:
   ```text
   ✔ release complete
   ✔ root admin ready: <your email>
   ```
4. Copy the Railway domain.
5. In Supabase → **Authentication → URL Configuration**:
   - **Site URL**: `https://<your-domain>`
   - **Redirect URLs**:
     - `https://<your-domain>/auth/confirm`
     - `https://<your-domain>/auth/reset-password`
6. Open the app and sign in with the admin email/password.
7. Change the password, then create users in **User Management** and grant roles
   in **RBAC**.

For production password-reset email, configure custom SMTP in Supabase →
**Authentication → Emails**. Supabase's built-in mailer is rate-limited.

## Environment variables

The template prompts for the first six. The rest are derived with Railway
reference variables.

| Variable | Prompt? | Value |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | `https://<project-ref>.supabase.co` (no trailing slash) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Yes | Supabase anon key |
| `NEXT_PUBLIC_SUPABASE_SERVICE_ROLE_KEY` | Yes, sealed | Supabase service-role key |
| `DATABASE_URL` | Yes, sealed | Supabase Session pooler (port 5432) |
| `BOOTSTRAP_ADMIN_EMAIL` | Yes | Root admin email |
| `BOOTSTRAP_ADMIN_PASSWORD` | Yes, sealed | Root admin password |
| `SUPABASE_SERVICE_ROLE_KEY` | No | `${{NEXT_PUBLIC_SUPABASE_SERVICE_ROLE_KEY}}` |
| `NEXT_PUBLIC_SUPABASE_STORAGE_URL` | No | `${{NEXT_PUBLIC_SUPABASE_URL}}/storage/v1/object` |
| `NEXT_PUBLIC_SUPABASE_PUBLIC_BUCKET` | Optional | `erpblobPublic` |
| `NEXT_PUBLIC_SUPABASE_PRIVATE_BUCKET` | Optional | `erpblob` |
| `DIRECT_URL` | No | `${{DATABASE_URL}}` |
| `NEXT_PUBLIC_APP_DOMAIN` | Optional | `https://${{RAILWAY_PUBLIC_DOMAIN}}` |
| `NEXT_PUBLIC_BASE_URL` | No | `${{NEXT_PUBLIC_APP_DOMAIN}}` |
| `NEXT_PUBLIC_API_URL` | No | `${{NEXT_PUBLIC_APP_DOMAIN}}` |
| `NEXT_PUBLIC_APP_LOGO` | No | `${{NEXT_PUBLIC_SUPABASE_STORAGE_URL}}/public/${{NEXT_PUBLIC_SUPABASE_PUBLIC_BUCKET}}/assets/stellar-app-logo.webp` |

> `NEXT_PUBLIC_*` values are resolved at runtime, so changing them in Railway
> does not require an image rebuild.

## What the pre-deploy does

Railway runs this before switching traffic:

```text
node migrate/release.mjs
  → prisma migrate deploy        idempotent
  → seed RBAC roles/permissions  idempotent
  → bootstrap root admin         idempotent
  → bootstrap Supabase storage   buckets + fonts/logo
```

A failure stops the deployment before users see a broken app.

## Updates

Railway image auto-updates are enabled for **minor and patch** releases. The
template pins `1.0.0`; Railway moves the service to `1.0.x` / `1.x` during the
maintenance window.

- To pin a version, change the service image to
  `ghcr.io/app-corp/stellar:<version>`.
- Major releases are not auto-applied; update the template/service image.
- To disable auto-updates, turn them off in the service settings.

Because this template uses a Docker image source (not a GitHub repo source),
Railway template update notifications do not apply. Image auto-updates are the
update mechanism.

## Custom domain

1. Railway → service → Settings → Networking → add your domain.
2. Update `NEXT_PUBLIC_APP_DOMAIN` and `NEXT_PUBLIC_BASE_URL` in Railway.
3. Update Supabase Auth Site URL and redirect URLs.
4. Redeploy.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `P1001` / database timeout | Use the Supabase **Session pooler** (port 5432), not the direct IPv6 connection. |
| `prepared statement "s0" already exists` | You used transaction pooling without `pgbouncer=true`. Use the session pooler. |
| Migration auth failure | URL-encode the database password; confirm `DIRECT_URL` uses the session pooler. |
| No menu / 403 after login | Sign in with `BOOTSTRAP_ADMIN_EMAIL`; sign out and back in to refresh permissions. |
| Reset link points to `stellarapp.site` | Set `NEXT_PUBLIC_BASE_URL` to your Railway/custom domain and update Supabase Auth URLs. |
| Uploads fail | Check pre-deploy storage logs and the service-role key. Buckets: `erpblobPublic`, `erpblob`. |
| PDF fonts fail | Public bucket must contain `fonts/inter-*.ttf`; re-run the pre-deploy. |
| Railway cannot pull image | The GHCR package must be public. Maintainers: package settings → Change visibility → Public. |

## Maintainer

### Template source

The source project is defined in `.railway/railway.ts`:

- image `ghcr.io/app-corp/stellar:1.0.0`
- image auto-updates `minor`
- pre-deploy `node migrate/release.mjs`
- healthcheck `/api/health` (120s)
- public HTTP networking

Variables are intentionally configured in the Railway template composer:
template prompts, sealed inputs, and reference variables are not part of the IaC
DSL.

### Create and publish

```bash
railway login
railway link
railway config plan
railway config apply --yes

railway templates create --project stellar-public --json
railway templates publish <template-id> \
  --category "AI/ML" \
  --description "Stellar AI Business Operating System" \
  --readme-file README.md \
  --json
```

Then copy the generated template URL/code into the button at the top of this
README.

### Release images

Images are published from [app-corp/stellar](https://github.com/app-corp/stellar)
when a `v*.*.*` tag is pushed. See the
[deployment guide](https://github.com/app-corp/stellar/blob/main/docs/engineers/deployment-railway.md).
